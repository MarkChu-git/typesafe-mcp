# Box：Jev 在截图里框东西有多准

2026-10-23，jev-1.14.0，`jev-latest` 和 `jev-preview` 现在都指向它。直接调 TypeSafe API，没有经过 agent。代码是 PR #42：`jev_ask` 在 `TYPESAFE_IMAGES=1` 时多了 `box` 题型。实验一共发了 50 个请求，Jev 那边用了 137,760 个 input token。

## 问题

TypeSafe 10 月 14 日加了 Box 题型：给一张图和一句"要找什么"，Jev 回答它在图里的位置。答案是一个框的上、下、左、右四条边，每条边是占图片高或宽的比例，从左上角量起。官方把它标成 dreamer-ready，请求里要带 `TypeSafe-Danger-Zone-Images: true`。

这个仓库最看重 agent 的 token。agent 自己打开一张 1280×720 的截图，上下文里要多大约 1,300 token；问 Jev 要一个框，结果只有两百来个字符。前提有两个：框要准，Jev 没把握的时候要看得出来。这次就量这两件事：框离真实位置差几个像素，置信度能不能用来决定信不信这个框。

## 怎么测

截图用 `screenshot-triage` 任务里的那 40 张，都是 `generate.ts` 从 HTML 渲染出来的。标准答案这样拿：

- 用 Playwright（playwright-core 1.64.1）驱动渲染截图的同一个 Chrome（155），按 1280×720、缩放 1 打开同一份 HTML，读元素的 `boundingBox()`。这次用到 15 个页面，Playwright 截的图和工作区里的 PNG 逐像素比对，一个不同的像素都没有，所以这些坐标就是截图里的坐标。
- 按钮、横幅、弹出提示、加载圈和角标有自己的底色或边框，用元素本身的框。没有底色的文字，包括两条表单报错、"500"、logo 和页头的 Cart (3) 链接，用紧贴可见像素的框。元素本身的框会把行高或整行宽度算进去，比看得见的字大一圈。

一共 22 个目标，分布在 15 张截图里。18 个真在图里，大小从 49×15 到 1200×48 像素；另外 4 个故意问图里没有的东西，比如在首页找报错横幅。

每个目标问两道题。Box 题写成 "the Checkout button in \`content\`"，再配一道是非题 "Is there a Checkout button in \`content\`?"。同一张截图的题放在一个请求里，state 是 `{file, content}`，和 `jev_ask` 的 `files` 发出去的一样。这组请求跑了 3 遍：`jev-latest` 两遍，`jev-preview` 一遍，三遍都由 jev-1.14.0 回答。

每个框算三个数：

- 边的误差：Jev 的每条边换算成像素，和真实位置差几个像素。
- 重合度（IoU）：两个框重叠的面积，占两个框合起来那块面积的比例，1 是完全重合。
- 中心命中：Jev 那个框的中心点落在真实元素里，也就是照着框的中心点一下，能点中这个元素。

## 结果

3 遍合起来是 54 个框、216 条边。误差中位数 5.7 像素，90% 在 14.4 像素以内。API 给的坐标只有两位小数，在 1280×720 上一格是横向 12.8、纵向 7.2 像素：光是把真实位置四舍五入到两位小数，误差中位数就有 1.6 像素，最大 6.4 像素。

按置信度分组，阈值用服务器的默认值：

| 置信度 | `decision` | 真在图里的框 | 其中中心命中 | 不在图里的目标 |
| --- | --- | --- | --- | --- |
| ≥ 0.8 | act | 44 | 44 | 0 |
| 0.5 到 0.8 | review | 10 | 1 | 0 |
| < 0.5 | abstain | 0 | — | 12 |

置信度 0.8 以上的 44 个框全部命中，边的误差中位数 4.7 像素，最大 25 像素。没命中的 9 个框，置信度都在 0.56 到 0.71 之间，会被标成 review。

### 框不准的地方

1. 表单下面的红色报错文字，143×12 和 176×14 像素：Jev 框的是输入框那一整行。左边和上下差不多对，右边多出去三百多像素，正好到输入框的右边缘。三遍都这样，置信度 0.56 到 0.61。换成 `the text "Card number is invalid."` 或者 "the red error text under the card number field" 来问，框基本不变，置信度 0.47 到 0.64。
2. 页头的 Cart (3) 链接，49×15 像素：框往下偏了十几像素，中心点落在文字下面，置信度 0.69 到 0.71。换成 `the text "Cart (3)" in the top-right corner` 来问，框几乎没动，置信度却升到 0.88，成了 act。这是这次唯一一个置信度过了 0.8 却点不中的框。这个链接只有 15 像素高，比两格纵向坐标多一点。

### 图里没有的东西

4 个不存在的目标，Jev 照样给了框，每遍还不一样。比如在购物车页找加载圈，三遍的框是 947×295、102×295、947×295 像素。这些框的置信度只有 0.02 到 0.16，配的是非题都答没有，p(是) 不超过 0.01。这组样本里，单看置信度也能把它们分出来。不过官方说 Box 没有"找不到"，这时的框本身没有意义，还是要靠是非题来判断。

### 其他

- 同样的请求重跑，答案会小幅变动。第 1 遍和第 2 遍的 44 个答案里有 23 个不一样：真在图里的目标，边最多差一格（0.01），置信度最多差 0.04，是非题的 p(是) 最多差 0.09（Cart 链接那题）。
- 一个请求里多问几题，看不出影响。Checkout 按钮单独问是 0.87，配上是非题也是 0.87，和购物车页的其他题一起问（一共 6 题）是 0.86 到 0.89。另一个会话之前问过一次，是 0.91。
- 每个请求大约 2,740 个 input token，几乎都是图片；多一对 Box 题和是非题，多 30 到 40 个 token。延迟中位数 277 毫秒，最长 480 毫秒。
- 通过 `jev_ask` 问一次 cart.png 有没有 Checkout 按钮、它在哪，agent 读到的结果是 202 个字符：

```json
{"files":{"screenshots/cart.png":{"there":{"answer":true,"certainty":0.98,"decision":"act"},"checkout":{"answer":{"top":0.39,"bottom":0.47,"left":0.74,"right":0.81},"certainty":0.88,"decision":"act"}}}}
```

## 结论

1. 有自己边界的元素，比如按钮、横幅、弹出提示、加载圈和大号文字，Box 框得够用。置信度 0.8 以上的 44 个框，照中心点都能点中，边的误差一般在 5 像素上下，最多 25 像素。
2. 没有底色的小字是短板。Jev 会把它框成一整行，或者框偏。置信度大多会掉到 0.8 以下，但换个问法，也可能在框偏的时候给出 0.88。
3. 服务器默认的阈值对 Box 也合适：act 的框可以直接用，review 的要自己核对，不在图里的目标全落在 abstain。
4. Box 题一定要配是非题。目标不在图里，Jev 也会给一个随手画的框。
5. 两位小数的坐标在 1280×720 上是 12.8×7.2 像素一格，目标只有一两格大时，框不会太准。

## 局限

- 页面是合成的，比真实页面干净；只有 22 个目标，图片也只有 1280×720 一种尺寸。
- 只测了 jev-1.14.0。TypeSafe 说 Box 的请求格式、答案和准确率都可能随版本变。
- 没测 agent。Box 能替 agent 省多少 token，要跑 agent 对比评测才知道，那要花钱，这次没跑。
- 文字目标的标准答案取的是可见像素；换一种量法，误差会差几个像素。

## 复现

脚本没有进仓库，步骤如下。

1. 标准答案：用 Playwright 启动本机 Chrome（`chromium.launch({ executablePath, args: ["--disable-gpu", "--hide-scrollbars"] })`，少了 `--disable-gpu` 截图就和工作区的对不上），视口 1280×720、`deviceScaleFactor: 1`。把 `generate.ts` 导出的 `html(screen)` 写成文件，用 `file://` 打开，对元素取 `boundingBox()`。文字目标在元素的文字范围里，找和背景色（这块区域里最多的颜色）相差超过 24 的像素，取它们的外接框。最后把 `page.screenshot()` 和工作区里的 PNG 比一遍。
2. 问 Jev：用 `src/client.ts` 的 `getClient` 建客户端，它带着 SDK 0.7.0 在 Bun 下的补丁。每张截图发一个请求，题目照上面的表：

```ts
client.systemOne(
  {
    state: { file: "screenshots/cart.png", content: image(bytes) },
    questions: {
      checkout: box("the Checkout button in `content`"),
      "checkout:there": noul("Is there a Checkout button in `content`?"),
    },
    model: "jev-latest",
  },
  { headers: { "TypeSafe-Danger-Zone-Images": "true" } },
);
```

3. 不存在的 4 个目标：home 找 "the red error banner"，cart 找 "the loading spinner"，product-mug 找 "the error toast"，checkout-shipping 找 "the error message under a form field"。
4. 通过 MCP 问：服务器设 `TYPESAFE_IMAGES=1`，`TYPESAFE_FILES_ROOT` 指向任务的 `workspace/`；`jev_ask` 的 `files` 传截图路径，`questions` 里放一道 `box` 题和一道 `noul` 题。
